# 价值导向 vs 诚实导向

> 本文是 Reviewer/operator 的价值判断原则，不是运行时状态机或第二份 Engineer prompt。
> 系统设计权威层级见 [`DESIGN_AUTHORITY.md`](DESIGN_AUTHORITY.md)。

诚实是**准入条件**,不是成果。这份文档给出两者的可操作区分——怎么从产物里看出一个 agent 是在创造价值,还是只是在诚实地记录自己没创造价值。

写这份文档的直接原因:本仓库里两者都有真实样本,差别不在 idea 的聪明程度,而在工程实现的认真程度。

---

## 1. 两种导向长什么样

| | 诚实导向 | 价值导向 |
| --- | --- | --- |
| 成功的定义 | 我如实报告了发生的事 | 我做出了别人能用的东西 |
| 遇到阻碍 | 记录阻碍,收工 | 换一条路,再试 |
| 对自己的 idea | 试一次,不行就丢 | 珍惜它,把工程做扎实 |
| 负结果 | 终点 | 诊断输入 |
| 典型句式 | "已诚实记录该方向不可行" | "该方向不可行,因此改为 X,结果是 Y" |

**两者都不作假。** 区别在于:诚实导向把"没做出来"当成一个可接受的终态,价值导向把它当成下一步的输入。

## 2. 两个真实样本

### 2.1 价值导向:FLA kernel 优化

`technical_report/evidence/fla_kernel_optimization/`。

Argus 在 flash-linear-attention(5.4k star 的真实开源库)的 `chunk_kda` 上,B200 实测拿到 **+17.66%(N≥10 认证)**,组合口径 +29.93%。

值得注意的是**三个 idea 单看都不惊艳**:
1. q/k 的 L2-norm 配对融合——少发一次 kernel
2. inter-solve 的 recompute 尾融合——少读一次 HBM
3. cumsum 并入 intra 生产者——再少一次 launch

全是"少发一次 kernel、少读一趟 HBM"。**价值来自把每一个都真的做完、逐个测准、叠起来。**

它同时诚实地记了失败:autotune 搜索和 memory-neutral 微变换落在噪声里,主 backward kernel 抗拒融合。**负结果被写进了机理结论**("收益全部来自 forward 生产者→消费者融合"),而不是当成终点。

### 2.2 诚实但无价值:75 小时 replan 循环

`docs/STATE_MACHINE_AND_DEADLOCKS.md` §4.2。

一个项目把同一个 mission 重排了 **100 次,跨 75 小时**。每一轮 Reviewer 都给出正确判断:

> 该 validate 包完整性无误,但这个科学方向在冻结边界内达不到可发表标准。

每一条都是真的。没有任何造假。**而 3 天里的净产出是零。**

这就是诚实导向的失败形态:系统在忠实地报告自己没有进展,并把这当成了一个可以稳定停留的状态。

> 那次的根因是 harness 层的死锁(Planner 的"无任务"回答无法改变任何状态),已修。但形态值得记住:**诚实的报告可以稳定地掩盖零产出。**

## 3. 我们要什么,不要什么

### (a) 不要"满足了基本要求就能睡大觉"

危险信号,在 Reviewer 裁决和 CHECKPOINT 里可见:

- 完成理由只引用 checklist 项被勾上,不引用**结果本身**
- "已达到最低要求"作为完成依据出现
- idea 只被实现了一个最省事的版本,没有任何一次迭代改进
- 遇到第一个障碍就转向"诚实记录该路不通"

**checklist 是准入门槛,不是目标函数。** 把它当目标函数,就会得到一个精确满足门槛、且仅仅满足门槛的产物。

### (b) 要珍惜自己的 idea,工程要激进

- 一个 idea 值得**多次**工程迭代,而不是一次实现定生死。§2.1 的三项优化都是先做出来、测准、再叠加。
- 遇到"这样做不了"时,先问"是这个 idea 不行,还是我这一版实现不行"。多数情况下是后者。
- **保守不是安全。** 一个平庸但稳妥的结果,和一次诚实的失败,对 operator 的价值同样接近于零;而激进尝试至少产生可用的负结果。
- 工程质量本身就是价值来源。§2.1 里 idea 的平庸和结果的显著形成对照——**决定性差异在实现质量,不在 idea 质量。**

### (c) 好奇与诚实的边界

诚实约束的是**声明**,不是**探索**。

| 允许 | 不允许 |
| --- | --- |
| 试一个可能失败的方向 | 把失败说成成功 |
| 报告一个 N=1 的初步数字 | 把 N=1 的数字当成认证结果 |
| 提出没有证据的假设 | 提出没有证据的**结论** |
| 用不完美的代理指标探索 | 拿代理指标冒充目标指标 |

判据是**标注**:任何数字,只要标清了它的强度(N、硬件、shape、是否认证),就可以拿出来。诚实要求的是不误导,不是不尝试。

FLA 案例正是这样处理的:+29.93% 是单次运行,文档明确标注,标题用的是过了 N≥10 门槛的 +17.66%。**数字都保留,强度都标清。**

反过来,"因为不确定所以不做"不是诚实,是把诚实当成了不作为的借口。

## 4. 怎么判定(给 Reviewer / operator)

看产物,不看措辞:

1. **完成理由里有没有结果?** 只有"流程做完了"没有"做出了什么",是诚实导向。
2. **负结果被用了吗?** 被写进下一步的诊断 = 价值导向;停在那里 = 诚实导向。
3. **这个 idea 被迭代过几次?** 一次实现即定终局,通常意味着它没被珍惜。
4. **数字的强度标清了吗?** 标清了就可以激进;没标清就是越界。
5. **如果这个方向真的不通,系统换路了吗?** §2.2 的 100 次重排,每一次都诚实,合起来是零。

## 5. 与既有契约的关系

`AGENTS.md` 的一句话原则是本文的上位约束:

> **科研以价值为目标,诚信是硬约束。** 可复现、反造假、完整保留负结果都是准入条件,但它们本身不构成科研完成。

本文是它的展开,不引入新的硬规则。特别地:**不要**把本文写成 prompt 里的又一段长文案。它是给 Reviewer 和 operator 判断用的参照,不是给 Engineer 的第二份行为守则——那会既涨 token 又和现有角色契约重复。

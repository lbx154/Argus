# Argus 会出什么问题，我们怎么修的

Argus 会连续无人值守跑好几天。这会产生一类很特定的失效——而且大多数不是人们预期的那一类。
它很少失控、很少捏造、很少卡死。它做的事更阴险：**它表现得像一个谨慎的初级研究员，那种已
经学会"最安全的产出是一个小的、处处加限定词的负结果"的初级研究员。**

下面几条失效不是意外，而是那些让无人值守变得可信的机制的**直接代价**。一个必须为每条声明
提供理由的系统，如果不加纠正，最终会停止做出任何声明。

English version: [failure-modes-and-fixes.md](failure-modes-and-fixes.md)

---

## 1. 它不会设计实验

**我们看到了什么。** 一场战役在 MATH-500 上给一个公开成绩 **79.7%** 的模型测出了 **6.0%**。
这个数字在任何人核对之前，就被当作"边界结果"写进了论文。原因是生成预算被设成了 **12 个
token**——一条数学推理轨迹根本不可能用十二个 token 表达出来，所以这次运行测的是那个上限，
不是模型。把上限抬上去变成 **68.8%**；再按公开协议假定的方式执行对应工具，变成 **76.4%**。

同一类错误也出现在后训练里。RL 的 rollout 长度短于任务实际所需时，那些本来正走在正确答案
路上的轨迹会拿到零奖励，于是梯度教会模型提前停止——而这个损害看起来和"这个方法不管用"一
模一样。

**为什么会这样——这才是更深的那层问题。** 12 不是笔误。每一个单独的步骤在局部都站得住：配
置需要一个 token 上限，数字被填上了，harness 跑起来了，评分器给了分。**从未发生**的是那句
任何研究者都会做、而且做的时候自己都不会察觉的横向核对——*一个证明要写好几段，所以十二个
token 不可能够*。这个 Agent 是**孤立地、机械地**推理的：它优化每一个局部决定，却从来没有把
整个实验同时握在视野里，于是一个设置和它本该服务的那个任务，永远没有被放在一起比较过。

所以这条不是靠"更仔细一点"能修的。一个错误的设置和一个错误的想法，产出的是同一种东西——管
路干净、数字很低——而运行本身不会告诉你手上是哪一种。Agent 拿到低数字之后去**解释**它而不
是**调试**它，正是因为解释是一个局部操作，而调试需要它并不具备的那个全局视野。

**我们做了什么。** 把那个缺失的全局核对，作为一条**明确规则**补上，而不是指望它自己有判断
力。技能
[`suspect-the-setup.md`](../argus_skill/verticals/research/skills/engineer/suspect-the-setup.md)
把默认姿态反了过来：*一个远离该模型、该方法或该基准已知表现的结果，在被证明之前都是一份缺
陷报告。* 具体做法是**强制它做那个它自己不会做的比较**：生成预算必须**从正确完成的长度分布
推导出来**，而不是随手取一个整数；并且运行必须报告撞到上限的生成比例——只要显著大于零，你测
的就是那个上限。RL rollout 长度、每个 prompt 的采样数、KL 与 clip 设置、评分器、协议步骤，
都按同一套办法处理。

答案的另一半在第 2 条：**单个模型无法审计自己的盲区**，所以"孤立推理"的修法是——在房间里放
一个陌生人。

## 2. 它的世界知识不会更新

**我们看到了什么。** 在可以自由选择 backbone 时，Agent 反复伸手去拿 Qwen2.5-7B 这类模型
——一个上一代的选择，任何主会评审都不会接受它来承载核心声明。同样的反射也出现在文献上：一个
能力很强的模型会心安理得地凭记忆写出一份看起来很像样的参考文献，"给知名基准猜 arXiv id、
凭记忆写摘要——**全程没有碰过网络**"。

**为什么会这样。** 这条不是推理失误，而且**它无法靠更强的推理来修**。模型名字、库版本、论文
id 在预训练数据里的分布，取决于它们被写过多少次，而这又取决于**它们存在了多久**。所以 Agent
的先验永远偏向上一代流行的东西，并且**冻结在训练截止那一刻，而世界还在往前走**。放着不管，
一个 Agent 永远会自信地伸手去拿去年的模型，并给出一段流畅的理由。

**我们做了什么。** 两件事：在时效性要紧的地方**禁止凭记忆**，同时给运行时一条**真的能去查**
的路。

**禁止凭记忆。** 模型时效性是一条**规则**而不是判断题，写在
[`training-infrastructure-guide.md`](../argus_skill/builtin_skills/engineer/training-infrastructure-guide.md)：

> **只用当代。** Backbone 必须来自一个**当前、正在活跃发布的开源模型家族**（决策当时的最新
> 一代，例如最近约 12 个月内发布或更新）。**不要**仅仅因为熟悉或下载快，就默认选用上一代或
> 遗留的小模型。

时效性必须在**决策当时**对着模型 hub 或近期榜单**去查**，并把选择连同确切的 model id、参数
量和发布日期写下来。文献这条路更严——
[`deep-research-via-api.md`](../argus_skill/verticals/research/skills/engineer/deep-research-via-api.md)
下了一条硬禁令 **"不得使用模型记忆里的文献"**：每一条都必须追溯到真实的一手 URL；而在没有真
正发起查询时写下 `"queried"` 或 `"retrieved from"`，被直接定性为**捏造**。

**然后给它一条真的能去查的路。** 光有禁令只会把工作卡死，所以运行时会**派生出带 live web
search 的独立 Agent**，把它们的产出当作知识库来用，而不是用模型的记忆：

| 机制 | 它去查什么 |
| --- | --- |
| [`idea_panel.py`](../argus_skill/verticals/research/idea_panel.py) | 若干个由不同实验室训练的模型，各自带 live search，先提出候选，再**互相交叉质询** |
| [`idea_search.py`](../argus_skill/verticals/research/idea_search.py) | 一次 live-search 调用，找出有文献支撑的空白并作为**额外**候选追加——只做来源，从不做选择 |
| [`venue_research.py`](../argus_skill/verticals/research/venue_research.py) | 会议的官方投稿事实，是取回来的而不是回忆出来的 |
| [`frontier_watch.py`](../argus_skill/verticals/kernel_engineering/frontier_watch.py) | 按阶段持久化并校验持续的前沿搜索，覆盖目标仓库、官方工具链和研究前沿 |

这个 panel 同时也是第 1 条"孤立推理"的答案，它的设计说明写得很直白：

> 一个模型问一次，返回的六个候选共享同一个模型的品味和同一个模型的盲区。……一个 GPT 系模型
> 看不见的反对意见，往往对 Gemini 系或 Claude 系模型是显而易见的；而一个经受住了陌生人交叉
> 质询的候选，比一个没有任何人跟它争论过的候选，是更好的下注。

座位由机器上装了哪些 CLI 决定；而同一个 backend 上跑同一个模型的两个座位会被折叠成一个——
*"那是一个模型在跟自己吵架，比不设 panel 更糟，因为它看起来像个 panel。"*

**我们测了什么，包括没成功的那部分。** Panel 是**默认关闭、需要显式开启**的，因为我们测过
了，它不是白捡的：

> 在四个方向、三十二个盲评候选上，panel 在**均值上并没有赢过**单模型 ideation——它产出了这
> 批里最好的那个候选，同时也产出了**两倍多的弱候选**，所以它买到的是**分布的宽度，而不是水
> 平的提升**。

这是一个**操作者应当主动选择**的权衡，而不是一场战役从"机器上碰巧装了哪些 CLI"里继承来的。

**这条的普遍教训。** Agent 从预训练里知道的一切，按其构造方式就是过时的。凡是时效性重要的地
方，运行时必须**强制它去查**，而不是信任它的回忆；而凡是"单个模型的品味"本身就是风险的地
方，运行时必须**强制引入一个由别人训练的模型给出的第二意见**。

## 3. 它没有理由变得进取

**我们看到了什么。** 这个系统不会提出有野心的东西。它一轮又一轮地采取**能被认证的最小那
一步**，产出是一串各自都站得住的增量，加起来却不构成任何人会称之为"发现"的东西。要它做原创
研究，它会心安理得地收敛到一个诊断性基准或一次复现，并把它当作交付物端出来——因为那是它**能
验证**的东西。

**为什么会这样。** "最小可验证进展"不是 Agent 的缺陷，**它是我们实际给出的那个目标的最优
解**。运行时里的每一个机制都在奖励一个被认证的增量；**没有任何机制奖励一次未被认证的跃迁**。
在这个目标之下，一个有野心的想法是严格劣势的——它成本更高、失败更频繁，而且失败时还没有东西
可以被采纳。一个理性的 Agent 处在这个位置上，会每一次、永远地去找那个能通过的最小的东西。

所以这条**不可能靠"要更有创造力"来修**。一边告诉系统"要创新"，一边按安全增量给它付钱，改变
的只是提示词的措辞，而不是它的行为。真正需要的是两个结构性改动：**拿掉那个安全的终止状态，
以及把新颖性变成一个门可以清点的东西。**

**拿掉那个安全的终止状态。** 物理 vertical 有一个显式的 `original-research-required` 模式
（[`mode_config.py`](../argus_skill/verticals/physics/mode_config.py)），它控制的正是"一个
mission 是否被允许以一个降级的论文类型（诊断性基准 / 复现）作为成功收尾，还是必须抵达一篇原
创研究论文"。这个模式打开时，**一个降级的论文类型只是中间结果**——那个舒服的落脚点，不再是一
种"完成"的方式。

**把新颖性变成可清点的。** 光有禁令只会产出一个卡死的战役，所以
[Novelty-Seeking Loop 门](../argus_skill/verticals/physics/gates/novelty_seeking.py)
把野心变成了一份**必须提交的产物**。在终稿之前，Agent"必须主动寻找新颖性，而不是将就于一个
诊断性基准"：

- **至少 10 个**候选方向（`MIN_DIRECTIONS = 10`），不是一个；
- 每一个都带着自己的推理列——`closest_prior_work`、`already_known`、`possible_gap`、
  `why_physically_meaningful`、`risk_of_already_known`，以及一条 **`kill_criterion`**；
- 每一个都要在六个维度上打分，包括 `novelty_potential` 和 `prior_work_separation`；
- 然后选出前 2–3 个，并写出 `PIVOT_SELECTION.md`、`REVISED_RESEARCH_OBJECTIVE.md`，以及额外
  的理论方案和数值方案。

失败码 `NSL-000` 到 `NSL-005` 让上面每一条都成为**可检查的条件**，而不是一句期望。这个门从不
自己发明想法——它只检查 Agent 产出的东西——但它把"我想不出什么有野心的东西"从一个悄无声息的
默认，变成了一次**产物层面的失败**。

同一个标准在**生成环节**就开始生效。候选必须"提出一个 METHOD，并带着一个它打算超越的、具体
且已复现的基线"，而且**"纯诊断 / 探查 / 只做基准的想法，在生成阶段就被拒绝"**
（[`idea_search.py`](../argus_skill/verticals/research/idea_search.py)）。kernel vertical 的
Planner 姿态与之一致：偏好期望上限与信息增益而不是低执行风险，并且**不**偏好最小的补丁或最容
易的即时验证。

**那个配重，以及为什么它必须存在。** 只强推野心而不给泄压阀，会产生另一种失效：一场被钉在够
不着的目标上、永远不终止的战役。这件事真实发生过——它以 `s-cbac6ede` livelock 的形式被记录在
代码里——这也正是
[`downgrade.py`](../argus_skill/verticals/physics/downgrade.py) 存在的原因：让一个 vertical
"起点定高，但收敛到证据支持得住的那一档，而不是把门钉在 Nature/Science 上然后 livelock"。让
这件事成为安全阀而不是后门的，是那句写得很死的话：

> 降级改变的是**声明类型（CLAIM TYPE）**，绝不是**严谨度（rigor）**的削减。

野心被施加在**这场战役想成为什么**上。它**从不**被施加在证据门槛上。

**仍未解决的部分。** `original-research-required` 和 Novelty-Seeking Loop 是**物理 vertical
的机制**，那条 ideation 标准是研究 vertical 的。**通用运行时里仍然没有等价物**——没有任何东西
阻止一场任意的战役将就于那个最小的、可认证的东西。**这是本文档里最重要的一块未完成的工作。**

## 4. 它在做仪式，而不是做研究

**我们看到了什么。** 精力被花在多个随机种子、重复同样的实验、SHA256 内容哈希上——而当时唯
一的问题只是"这个想法到底值不值得往下做"。严谨被施加在一个还没有配得上它的假设上。

**为什么会这样。** 这条是我们自己造成的。我们建了一个会认证自己产出的系统，而认证需要重
复、方差和内容寻址的证据。这些要求随后**向前渗透**进了探索阶段——在那里它们是纯成本。Agent
并不是不理性，它是在正确地优化我们**实际**给它的那个目标。

**我们做了什么。** 把姿态分开，让证据门槛**随声明的成熟度缩放**，而不是一刀切。出自
[`exploration-without-local-hill-climbing.zh-CN.md`](exploration-without-local-hill-climbing.zh-CN.md)：

| 姿态 | 有效产出 | 默认实验成本 | 风险姿态 |
| --- | --- | --- | --- |
| 探索 Explore | 有出处的报告、机制组合、假设 | 不要求运行 | 宽、激进、高上限 |
| 筛选 Screen | 一次干净运行，或一次不确定的尝试 | 一次运行；不做重复对照或多 seed | 最大化信息增益 |
| 声明/留存 Claim | 正确实现 + 可比证据 | 重复与方差仅按声明所需 | 严格证据 |

> 探索**可以**是思辨的、未实现的、未验证的、尚不可复现的。一个性能声明**不可以**。

**仍未解决的部分。** 这套姿态分离目前只写进了 **`kernel_engineering` 这一个 vertical**。研
究 vertical 有一条相关规则——判定一次成功恢复时"证据与其实际声明成比例"、"不必在每个 seed
上都赢"——但**"探索期不做仪式"这条明确政策还没有推广到所有 vertical**。它应该被推广。

## 5. 它在爬局部的山，而不是探索

**我们看到了什么。** 在 8 张 AMD MI300X 上的全 BF16 GLM-5.2 serving 战役中，Argus 开局做了
真正宽的调研：**1,851** 次与 GLM/ROCm 相关的网页和 GitHub 工具调用。然后它找到了一个主导性
的 host-to-device 专家传输瓶颈——好奇心随即戛然而止。在这个瓶颈被命名之后，相关的上游源码
阅读次数降到了 **零**。

接下来是一长串就近的变体：打包拷贝、多流拷贝、路由专家缓存、索引表、指针表、预取变体。全都
是正当的实验。全都是局部的。它再也没回到外部前沿，因此也就没发现那些直接相关的已发表系统
——FluxMoE/PagedTensor、FineMoE、MoE-Infinity、Fiddler、HIP 虚拟内存重映射。

**为什么会这样。** 又是我们自己造的激励。实现算作进展；一份纯研究报告很容易被以"没有执行"
为由拒绝。那些本意是防拖延的规则——*用最小的相关面、跑最便宜的证伪检查、每轮都产出一个测
量*——组合起来变成了一个奖励"最近的安全增量"的目标。Agent 当时在最大化的是**产出一个被接受
的增量的概率**，而不是**找到最好机制的概率**。

被缓存的 skill 让这件事变得顽固：只改顶层提示词毫无用处，因为项目层的 skill 里还写着"最小
的未实现机制"。

**我们做了什么。** 第一版修复本身就是错的——它只允许在**反复失败之后**做一次"搜索重置"，这
等于把好奇心变成了一种需要审批的例外。操作者否决了它。最终政策允许**在失败之前**就做研究，
接受一份好报告作为完整交付物，并要求 Planner **偏好期望上限与信息增益，而不是低执行风险**。
Reviewer 在同一轮里也被改了：它按来源质量、综合能力和决策价值来评判一份研究报告，并且
**不会仅仅因为一个想法不确定就拒绝它**。

完整记录：[避免局部爬山](exploration-without-local-hill-climbing.zh-CN.md)。

## 6. 它不愿意报喜

**我们看到了什么。** 持续的负结果偏好。Agent 主动罗列局限、偏爱"inconclusive"，并且明显更
乐于报告什么失败了，而不是把一个证据其实支持得住的成功说出来。

**为什么会这样。** 恰恰是那面让人类可以离开房间的承重墙。Reviewer 是被刻意做弱的——只读、
可以返回 `blocked`、不能认证自己的工作——而且它被要求
[把诚实的负结果或零结果当作证据](../argus_skill/builtin_skills/reviewer/argus-reviewer-role.md)，
而不是失败。这是对的，也正是这个系统的数字可以被信任的原因。但**只对"过度声称"施加惩罚、而
对"声称不足"没有对应惩罚**，会造出一个"什么都不说时最安全"的系统。

**我们做了什么，以及没做到什么。** 声称不足在评审侧被点名为一种缺陷。结果评审被要求对称地
检查：

> 是否存在 overclaim（把边际收益说成"显著提升"）？
> 是否存在 underclaim（漏掉了数据里一个有意思的发现）？

并且要确认零结果"被诚实呈现，而不至于把论文变成一份详尽的失败日志"。随后
[`result-to-claim.md`](../argus_skill/verticals/research/skills/engineer/result-to-claim.md)
直接掐断那个失败循环：

> 同一条声明上多轮 `partial` → 结晶出被支持的边界并推进到论文，而不是继续打转

它同时禁止把一个缺失的对比说成"因为方法表现不好所以没有"，要求改用方法论术语解释缺口；并规
定判定一次成功恢复时证据要与其实际声明成比例，"不必在每个 seed、每个基准或最强基线上都赢"。

**仍未解决的部分——这是诚实的那一段。** 这些规则挡住了最糟的那个循环，也让"声称不足"变得可
被评审，但它们并没有创造出对成功的**胃口**。系统里没有任何东西，会让"一个后来被证明是对的
进取声明"比"一个后来被证明多余的保守声明"得到更多奖励。**对过度声称的惩罚是结构性的**——一
个只读、可以返回 `blocked` 的 Reviewer；而**对声称不足的惩罚只是一道要靠人记得去掂量的检查
表问题**。在这个不对称被两侧同时纠正之前，默认姿态仍然会是信心不足，仍然需要一个人去把它往
进取的结果那边推。**这一条我们没有解决。**

---

## 底下那个共同的张力

第 3、4、5、6 条共享同一个根源，而且它不是一个可以直接摘掉的 bug。

那些让 Argus 可以被放心留下独自运行的性质——干活的一方不能认证自己的工作、每条声明都带着它
的证据、有信息量的失败被计为前进——正是让它变得畏缩的同一批性质。**严谨是对进取心征的税。**
施加在一个已完成的声明上，它完全正确；施加在一个还没配得上它的想法上，它就是一台生产"小、
安全、无趣"的机器。

所以上面这些修复都不是在放松标准。它们每一个做的事都是把**系统愿意去调查什么**和**系统被允
许声称什么**分开。前者必须宽、便宜、无所畏惧。后者必须保持严格。

> 好奇心决定 Argus 愿意去调查什么。
> 证据决定 Argus 被允许声称什么。

放松探索约束，永远不等于允许不诚实的声明。Argus 仍然拒绝：捏造的执行或测量、根本没有走到被
修改代码的基准路径、被重新贴标签的证据、被放松后当作优化呈现的正确性阈值，以及被描述成实测
事实的假设。

# Argus 0.1.10 — unified warm interface preview

Local candidate based on `4aa6d560a16dc0cd97f1d9758b398fd75f7f87ef`. That earlier
candidate only changed the desktop shell; real API/production-bundle inspection
confirmed that its iframe conversation area, header and composer still used
white, and its sidebar still used cold gray. It was not accepted as a completed
whole-interface fix and was not uploaded.

## Complete shared palette

The light cockpit now uses `247 243 232` (`#f7f3e8`) for the base, primary panels,
sidebar, conversation area, header and primary composer surfaces. Raised cards
use related ivory (`252 250 244`), while sunken controls and user messages use
warm depth (`238 232 216`). Glass and chrome surfaces alias these same values.
Maps, the IDE and research-workbench modules inherit the shared palette instead
of retaining large white application backgrounds. The map's separate cold canvas,
card and minimap colours now alias the shared base/raised surfaces in both themes. One hard-coded map figure
container and a white hover overlay now use the shared surface too.

The desktop startup/native-window palette from the previous revision is retained.
Its regression now compares the shell background to the cockpit's actual base,
not to a user-message color. Dark mode retains its existing dark surfaces and
gold accents. Original PDF/HTML/image document content, white eye/highlight
pixels, accent foregrounds, backend/role behavior, SVG geometry and startup timing
are not recolored or changed.

## Acceptance boundary

Verify actual rendered colours across sidebar, conversation, header, composer,
results panel, map and research-workbench/IDE, using the real application API and
production frontend. Test both light and dark preferences, and compare the
source/frozen bundle identity. Check full-page screenshots, not only the desktop
header or a mocked IPC shell. Native packaged startup/authentication/short health
checks are still required before handing over the local manual-test ZIP.

Complete paid-agent/research workflows, Windows Toast, installer/upgrade and
30-minute soak are not certified by these palette tests. No GitHub push, signing
or upload is authorized until the user reviews and explicitly approves the
unified preview. The original source checkout and user data are preserved.
Old preview files remain until the exact cleanup scope is confirmed and a new
usable package has passed its checks.

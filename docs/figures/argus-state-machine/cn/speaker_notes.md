# 01_state_machine

这张图展示的已经不是风险诊断，而是修复后的真实状态机。Planner 产生的普通计划和 replacement 都先经过整批环检测再原子写入，Backlog 在读取 next pending 和真正领取任务时都会执行相同的依赖清理，因此遗留环、缺失依赖和失败依赖会进入明确的 skipped 终态，而不是伪装成空队列。工程师与审查者仍保留同范围迭代内环，但跨范围重规划必须携带计划版本并通过 compare-and-swap 提交；连续三次没有可提交 replacement 时，当前节点 fail-closed。暂停、回答和升级也都获得独立退出边：外部可恢复暂停自动开始新 attempt，操作员回答会重接全部下游依赖，长实验期间的升级请求立即返回并在自然边界后继续执行；已完成 workspace 接收新 intent 时还会重新打开 terminal stage。

# 02_deadlock_atlas

第二张图逐项给出十三个原始活性风险的关闭证明。最高风险的六条路径由写入前环拒绝、读取时强连通分量终结、版本化计划替换、三次熔断、自动唤醒和依赖重接处理；五条持久阻塞路径则由 HOLD 终结当前节点、非阻塞升级复查、未定价成本保守占位、Manager 反馈熔断和带上下文哈希的去重签名处理。并发层统一使用先 pipeline 后 session 的锁顺序，Planner 没有 runner 或发生异常时进入十五秒到三百秒的指数退避，因此不会形成快速重试风暴。验证不仅覆盖单元路径，还包括扩大 life、Manager 和 daemon 测试、连续二十轮并发压力测试，以及完整的终端和网页前端测试；在这些验证中没有出现重复领取、重复 continuation 或无法退出的状态分量。

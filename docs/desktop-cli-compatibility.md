# Argus 1.0.0 桌面预览：CLI 兼容性与验收范围

验证日期：2026-11-01。分支：`feat/desktop-1.0.0-role-cli`。

这是本地功能预览，不是正式 Release。**“已接入适配”“协议回归通过”“真实账号运行通过”是不同结论，不能互相代替。**

## 已实现

- 经理、规划者、工程师、审阅者分别选择 CLI、模型和该 CLI 报告的推理强度。
- 配置按项目持久化；新项目继承最近创建项目的配置。保存使用版本检查，一次提交多个角色。
- 切换 CLI 会重新获取对应目录，不沿用另一个 CLI 的模型；当前调用保持原配置，下轮生效。
- 切换 CLI/模型后隔离旧会话；旧调用不能覆盖新配置，包含 A→B→A 的情况。
- 模型查询不提交推理任务；“测试此配置”才会发起真实调用，可能产生费用。错误可展开查看。
- 模型列表支持提供商限定 ID、搜索、自定义 ID、刷新和 CLI 默认项，不把固定的“默认模型”冒充完整目录。
- Windows 包内置 Node 24.19.0。预览使用独立应用标识、数据与 WebView2 存储，并禁用发布更新。

## 测试证据和边界

- 九种 CLI 的子进程协议回归通过；另外为九种 CLI 分别执行了四角色交接格式测试（共 36 条角色/传输组合）。这些是隔离的脚本 CLI 夹具，不是假称官方 CLI 的实机测试。
- 全部 81 个有向 CLI 组合的调度、独立模型/思考等级、角色会话隔离和重启恢复通过。此矩阵是调度层测试，不等同于 81 次真实账号调用。
- 已真实完成：Pi 经理/规划者 → DSH 工程师 → Pi 审阅者；DSH 经理 → Codex 工程师 → Pi 审阅者；DSH 经理 → Pi 工程师 → DSH 审阅者。
- DSH 审阅者一次输出未符合交接格式，被严格拒绝并纠正后才继续；没有把普通文字当作成功交接。
- 浏览器验收通过：真实 Pi/DSH 目录、独立配置保存、页面重载和窄屏布局，无推理调用。
- 实际打包的 Tauri EXE + WebView2 验收通过：首次设置、内置 Node 启动、真实目录、配置保存、独立数据根及禁用更新。没有替用户安装或覆盖旧版。
- 前端：137 个测试文件、1112 项测试通过。
- Rust：88 项通过，2 项为测试框架的隔离子进程入口而 ignored。
- 发布/签名/预览身份校验：21 项通过；文件复制校验：5 项通过。
- 上次全量工作区测试：654 项通过、5 项因 Windows 无符号链接创建权限而失败、14 项跳过；此后新增的九种 CLI 四角色测试也单独通过。未把这些权限阻塞伪装成通过。
- 旧桌面浏览器测试：41 项通过；40 项仍依赖旧 Python 测试夹具并启动失败（包括缺少 ijson）。需迁移/修复测试环境，不能声称全量 UI 回归全绿。桌面运行包本身不依赖 Python。

## 正式发布前仍须完成

1. 修复外部 CLI 鉴权/路由条件后，完成 Claude、Codex 及其余五种 CLI 的真实验证；或明确约定首版实机支持范围。
2. 完成旧 Python 项目/历史数据迁移方案和隔离升级测试。当前预览不自动导入或改写旧数据。
3. 修复/迁移旧 Python UI 夹具，并在具备权限的环境复核符号链接安全用例。
4. 用户验收本地包后，使用原发布者的安全签名配置生成正式安装包、`.exe.sig` 和 `latest.json`，完成 0.1.10 隔离安装/验签检查；正式发布后再复核真实 GitHub 更新链路。

正式版仍保留 `cn.argusbot.desktop`、原 updater 公钥及 GitHub latest.json 地址。不能用新生成的私钥冒充原签名体系，也不能把“自动检测更新”描述为旧版原本没有的“完全静默强制安装”。目前没有创建 Tag、推送分支或上传 Release。

# Argus · 一页纸概览

> **一句话**：给它一个研究目标 + 这台机器的规则，它就 **7×24 不停机、完全自主地做研究**——
> 选题、调研、设计实验、在**真实指标**上测量、分析、写代码、产出可复现的结论。
> 研究目标可以是一篇论文、一个逼近硬件极限的 **CUDA kernel**、一个要提速的**训练脚本**、一套要挖掘的**量化因子**——**共用同一套原则**。
> 它的本事不在「会写论文」，而在**把高密度智能任务一刻不停地执行下去：不空转、不打滑、不卡死。**
>
> *Argus — Autonomous Research Generation & Understanding System*

---

### 它是什么
一个**完全独立于人、长期自主运行的 research agent**。你只给「做什么」和「机器规则」，
它就自己一直干下去，没有人在回路里逐步审批。做研究的每一个**判断**都由 agent 自己下。

### 真正难的不是「做一次判断」，而是「连续几天不退化地一直产出」
长跑的自主 agent 会死在三件事上，Argus 把它们从**结构上**堵死（有默认值、有测试，不是 prompt 哄劝）：

- 🟢 **不空转**：长实验有独立监督进程自看护 → agent 不守着它、去拉独立工作；待办空了自动补活；
  一**群**并行 agent 从任务板领活，而非单线程串行。
- 🟡 **不打滑**：底层会话被反复有损压缩会「失忆—重读」原地空想（正常轮 ~200 万 token，失忆环涨到
  500–700 万）→ 用**硬上限的小工作记忆 + 会话定期换班**，根治这个失控。
- 🔴 **不卡死**：**语义**进度看门狗（看「项目有没有真前进」而非「挂没挂」）、停滞/活锁自动升级并交回
  Planner 重新拆解、卡死的并行 worker 硬超时杀掉改派。

### 一句话设计哲学
> **harness 没有 agent 聪明。**

智能判断（idea 平不平庸、做完没、该不该等这个 run）永远归 **agent**；承载程序只做**领域无关的笨管道**
（预算、存盘、调度、**执行护栏**、防造假护栏）。上面那些护栏管的是「**有没有在有效执行**」这种机械事实，
**不**替 agent 做研究判断——**任何用关键词/规则替 agent 二次判断的逻辑都被删掉**，否则 harness 就成了天花板。

### 怎么工作
- **Planner（规划）→ Engineer（工程）→ Reviewer（审稿）** 三个会思考的模型协作，可派生**带独立监督进程
  的并行 subagent / team 池**密集推进。
- **Reviewer 是「任务算不算完成」的唯一事实来源**（对照清单逐条裁决，无硬编码完成门），并兼任记忆审计员。

### 同一套 principle，多种研究问题
Argus **不是论文系统**。它的引擎是**领域无关**的，适合任何**长程·可度量·易作弊**的研究/优化问题——
有诚实的硬指标、有要在同等条件下打败的强基线、有要堵死的作弊捷径、需连续数天密集执行：

| 研究问题 | 真实指标 | 要打败的强基线 | 堵死的作弊捷径 |
|---|---|---|---|
| **CUDA kernel 优化** | 平均 SOL（1.0=硬件极限） | torch.compile≈0.547 | 硬编码输入统计量 → 评测输入随机仿射 |
| **训练脚本提速**（8×H100） | 达标的认证墙钟时间 | Recursive 185.4/80.6/77.3s | 偷换 kernel/环境漂移 → 强制环境对齐 |
| **训练效果**（nanochat） | 固定预算 val_bpb | Recursive 1.0587/0.9344/0.9109 | 假 attention shim → 用真实 FA-4 |
| **量化因子**挖掘/筛选/组合 | 样本外表现/组合收益 | 领域强基线 | 前视/泄漏/过拟合 → 样本外+可复现审计 |
| **自动写论文**（EMNLP/AAAI） | 通过完整同行评审 | 真实强基线复现 | pilot/合成冒充证据 → 全规模证据门 |

**共同点：拿一个诚实硬指标，在不作弊前提下连续数天逼近极限 / 打败强基线。** 第 2 节的执行护栏 + 诚信
护栏对它们是**同一套机制**，只是把关的指标不同。论文只是任务链最长、最能压测整套机制的那一种。

### 自进化：靠它啃下需要专业知识的 OOD 问题
一个引擎凭什么跨 kernel / 训练 / 因子 / 论文？这些都是 **OOD（超出基座模型分布）、需专业 know-how**
的问题——基座模型不「天生会」某架构的 kernel 陷阱、某训练栈的真实 FA-4 接法、某市场的因子构造。
Argus 不靠「换个更大模型」，而靠**自进化**把不会变成会，并沉淀成越用越准的能力：

- **缺能力当场长一个**：没有现成 skill 就在线蒸馏，作者 prompt 明确要求**联网看「从业者怎么解这类问题」**
  + 本机实测，写成实操手册；
- **每个任务后自动更新**：成功→强化、没命中→蒸馏、有教训→修订、连败→退役（一张 lifecycle 决策表）；
- **失败也沉淀**：被否决的方向留下可复用 skill/benchmark/审计，喂给下一次。

**结果：第 N 次碰同类专业问题时，手里已攥着前 N−1 次攒下的 know-how——「越跑越会」是决策表每个任务都在
执行的结果，不是修辞。** 而「记什么、哪条教训该提升」仍是 agent 的判断，harness 只做领域无关的机械触发。

### 为什么可信（诚信底线）
✅ 只用**真实公开 benchmark + 真实测量**　✅ 主动堵 **reward hacking**（如随机化评测输入）
✅ 基线**同硬件同脚手架**公平复现　✅ 全程**可复现审计链**　✅ **绝不报喜报早**

### 为什么值得关注
它解决的是「**自主 agent 怎么不退化地长跑**」这个真问题（领域无关），不是又一个能跑 demo 的壳；
**失败也有用**——每否决一个方向都沉淀出可复用 skill/benchmark/审计证据，越跑越强。

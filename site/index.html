Argus 快速上手

照着下面 6 步做，一小时内你会装好 Argus，交给它第一个任务，并在网页上看着它把活干完。每做完一步，勾选该步末尾的“我做完了”，页面会记住你的进度。

你会经历什么

Argus 是一个会长时间自己干活的研究和工程团队。你只和 Manager 说话；它把任务交给 Planner 拆解、Engineer 执行、Reviewer 审查，并在需要你拍板时停下来问你。

① 装好
一个 Agent CLI 加上 Argus 本身，约 15 分钟。
② 交任务
用一句话写清楚要什么、怎样算完成。
③ 看它干活
在地图上看任务拆成了哪些步、谁在做、卡在哪。
④ 拿结果
Reviewer 审过的文件，以及它是怎么得出来的。

这篇适合谁

  • 第一次用 Argus，想用最短的路径跑通一个真实任务。
  • 会打开终端、复制粘贴命令就够了，不需要懂 Argus 的内部结构。
  • 用 Windows、macOS 或 Linux 都可以；远程 Linux 服务器也行。

最快路径

经验法则

先只用一个后端跑通一个小任务，再去加别的后端、纵向或长期任务。大多数“装不好”的问题，都是一次改了太多东西。

1准备 Node.js 和一个 Agent CLI

Argus 自己不带模型，它驱动你已经在用的 Agent CLI 来干活，也不需要额外的账号。你需要：

  • Node.js 22.12 或更高，从 nodejs.org 下载。
  • 一个已登录的 Agent CLI。下面三个最常用，任选其一；完整列表见 README。
$ npm install -g @openai/codex@latest
$ codex login
$ npm install -g @anthropic-ai/claude-code
$ claude        # 进入后输入 /login 完成登录，再退出
$ npm install -g @github/copilot
$ copilot login
你应该看到
  • node --version 输出 v22.12 或更高。
  • 直接运行 codex / claude / copilot，能正常和它聊一句。

2安装 Argus

选你的操作系统，不要混用不同系统的命令。如果你已经装好了 Agent CLI，最省事的是第一个标签页：让它替你装。

把下面这段话原样发给你的 Codex / Claude Code / Copilot。它会按 Argus 的安装执行约定识别系统、安装、配置，并跑完自检。需要你登录或授权时它会先停下来问你。

Read https://github.com/microsoft/ArgusAgent/blob/main/docs/agent-install.md and
install the official source unless I explicitly request the development preview.
Keep an existing installation's channel when updating. Use the section for this
operating system. Prefer the Agent CLI running
this conversation as the Argus backend. Do not create a venv on Windows or
macOS; keep the documented venv on Linux. Run setup through its real Agent-turn
smoke test, then run `argus doctor --deep --advisor auto`. Before account login,
sudo, or global configuration changes, explain why and wait for approval. Never
ask me to paste a password, token, or API key into the conversation.

它做完后会给你一份报告，说明用的是哪个 argus、哪个后端和模型、自检是否通过。自检都通过的话，直接跳到第 4 步。

先装 uv，然后：

$ uv tool install --force --python 3.12 \
    "argus @ https://github.com/microsoft/ArgusAgent/archive/refs/heads/main.zip"
$ ARGUS_BIN="$(uv tool dir --bin)/argus"
$ "$ARGUS_BIN" --version
$ uv tool update-shell   # 新开终端后可以直接输入 argus

先从 python.org 安装 Python 3.11+，安装时勾选 Add Python to PATH。然后新开一个 PowerShell：

PS> py -m pip install --upgrade pip
PS> py -m pip install --upgrade --force-reinstall "argus @ https://github.com/microsoft/ArgusAgent/archive/refs/heads/main.zip"
PS> $Scripts = py -c "import sysconfig; print(sysconfig.get_path('scripts'))"
PS> $env:Path = "$Scripts;$env:Path"
PS> argus --version

想用带图形界面的安装包，看 Windows Desktop。

需要 Python 3.11+、Git，以及发行版的 python3-venv 包。Linux 上 Argus 固定装在自己的虚拟环境里：

$ git clone https://github.com/microsoft/ArgusAgent.git "$HOME/Argus"
$ cd "$HOME/Argus"
$ python3 -m venv .venv
$ .venv/bin/python -m pip install --upgrade pip
$ .venv/bin/python -m pip install -e .
$ alias argus="$HOME/Argus/.venv/bin/argus"   # 本页后面的 argus 都指它
$ argus --version
你应该看到
  • argus --version 打印出一个版本号，没有报错。

3配置并自检

--setup 会选好后端，并真的让模型跑一轮来确认能用；doctor 再把整套环境检查一遍。

$ argus --setup                         # 按提示选择第 1 步装好的 CLI
$ argus doctor --deep --advisor auto    # 发现问题时允许 Agent 帮你修
$ argus --config-help                   # 看每个角色实际用的后端和模型

想直接指定后端，可以写成 argus --setup --backend codex（或 claude、copilot 等）。

注意

doctor --advisor auto 会真的调用一次模型，可能要几分钟，也会消耗你的额度。只想快速确认、不调模型，用 argus doctor --advisor none --verify。

你应该看到
  • setup 结束时报告真实的模型回合通过。
  • doctor 没有报未解决的错误。

4建一个练习目录，打开驾驶舱

第一次请用一个新建的空目录，不要直接在重要项目里试。Argus 会在当前目录里干活。

$ mkdir -p ~/argus-first && cd ~/argus-first
$ git init -q
$ argus --web
PS> New-Item -ItemType Directory -Force "$HOME\argus-first" | Out-Null
PS> Set-Location "$HOME\argus-first"
PS> git init -q
PS> argus --web

浏览器会打开网页驾驶舱，默认地址是 http://127.0.0.1:8799（端口被占时会自动顺延）。界面支持中文，可以在会话侧栏的语言按钮切换。

什么都不用做，网页已经打开了。喜欢命令行的话，直接运行 argus 就能进入终端驾驶舱，两者看到的是同一个项目。

在服务器上运行 argus --web，然后在你自己的电脑上开一条 SSH 隧道，再打开 http://127.0.0.1:8799：

$ ssh -L 8799:127.0.0.1:8799 user@server

断开 SSH 后，后台任务会继续跑。

你应该看到
  • 一个对话框，可以和 Manager 说话。

5交出第一个任务

把下面这段话原样发给 Manager。它不需要 GPU，一般十几分钟就能完成，而且怎样算完成写得很清楚，这是写好目标最重要的一点。

在当前目录写一个 Python 命令行工具 wordfreq.py：
读入一个文本文件，输出出现次数最多的 10 个英文单词和次数（忽略大小写和标点）。

完成标准：
1. 用 pytest 写测试，至少覆盖：空文件、大小写混合、带标点；全部测试通过。
2. README.md 写清安装和用法，附一次真实运行的输出。
3. 不要引入第三方依赖（pytest 除外）。

发出去以后，Manager 会判断这是需要团队完成的工作，交给 Planner 拆成几步，再派给 Engineer。

为什么这样写
  • 要什么写在第一段：一个工具、输入、输出。
  • 怎样算完成单独列出，而且能检查：测试全过、README 有真实输出。
  • 不许做什么也写上：不引入依赖。Argus 会把这些当作你的边界，要改得先问你。

更多写法见 怎么写目标。

6看进度、插一句话、拿结果

看进度

在网页上打开地图：每个任务和它的每一步都在一张图上。点任务看它的子图，点某一步看细节。实线是依赖，虚线是内容上的关联。任务卡片会经过：目标 → 已规划 → 已领取 → 执行轮次 → 审查 → 要求修改。

在终端驾驶舱里，常用这几个命令：

命令作用
/status各角色在干什么、排队的工作、健康状况
/events搜索事件流：全部 / 关注 / 里程碑 / 消息
/backlog待办任务
/roles每个角色的后端、模型和当前活动

中途插一句话

任务跑着的时候，你随时可以补充要求。试一下，让它多做一件小事：

/nudge 再加一个 --top N 参数，默认 10，并补上对应测试

在网页上，直接在对话框里说同样的话就行。想先问问题、不想派活，用 /ask；要立刻停下当前任务，用 /abort。

拿结果

/artifacts

这里列出的是 Reviewer 已经检查过的结果文件，回车可以预览。文件本身就在你的练习目录里，可以自己再跑一遍：

$ cd ~/argus-first
$ python -m pytest -q
$ python wordfreq.py README.md
你应该看到
  • 测试全部通过，--top 参数也在。
  • README 里有一段真实的运行输出。
关掉也没关系

关闭网页或用 /quit 离开驾驶舱，后台工作会继续。想彻底停下，等当前任务到自然边界再停：argus --daemon-stop --drain，然后用 argus --status 确认。

自救工具箱

遇到问题按这个顺序试：

  1. argus --status：后台进程和待办在不在。
  2. argus --config-help：后端、模型实际是什么、来自哪里。
  3. argus doctor --advisor none --verify：不调模型的确定性检查。
  4. argus doctor --advisor auto：允许 Agent 检查并修复 Argus 自己的文件和配置。
  5. argus update：更新到当前渠道的最新版，然后重跑第 3 条。

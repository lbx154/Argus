# WebUI and Budget

## 动态 WebUI 渲染

由 Manager 根据当前任务判断是否渲染、何时渲染和渲染什么。Manager 输出少量
结构化 render intent，前端使用通用、可扩展 renderer 展示代码、diff、论文、公式、
表格、图表、实验数据、日志摘要或研究进度。

不要按任务名称或关键词硬编码页面，也不要默认渲染所有 artifact。未知 intent 或
渲染失败时安全退化为普通文本，不能阻塞主任务。对代码、Markdown、HTML、文件路径
和外部资源实施适当的转义、沙箱与权限边界。

视觉应克制、清晰、专业，支持实时增量更新，让当前少量高价值信息容易理解，而不是
堆积动画、卡片和长期无人查看的面板。

## 源头统一 Budget

把预算控制放到所有模型执行的共同源头，统一覆盖 `codex exec`、`copilot exec` 和
未来 backend。任何角色、重试、子任务、并发调用、session 恢复和 fallback 都必须
经过同一后端无关入口。

统一处理：

- 调用前预算检查或预留。
- 调用后按真实 usage 核账和差额调整。
- 失败、超时、取消、重试与并发。
- token、货币成本、backend/model 和调用归属的审计。
- 无法取得真实 usage 时明确记录 unknown 或 estimate。

先追踪全部现有调用路径和 budget 实现，再选择正确抽象接缝。删除被统一入口取代的
碎片化记账与兼容逻辑，不在旧层上继续包 wrapper。

测试应覆盖各 backend、并发、失败和重试，证明不存在绕过、漏记、重复记账或竞态
超支。预算数字是资源护栏，不替 reviewer 判断任务价值。

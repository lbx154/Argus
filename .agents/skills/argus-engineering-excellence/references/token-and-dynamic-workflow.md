# Token Efficiency and Dynamic Workflow

## 端到端 Token 效率

以“完成一个有效任务所消耗的端到端 token”为核心指标，而不是单次调用长度。
同时观察结果质量、成功率、可靠性、成本和 wall time，防止局部节省导致总体返工。

从真实任务 trace 查找根因：

- 重复上下文、重复读取和无效历史回放。
- Manager、Planner、Engineer、Reviewer 间重复转述。
- 不相关 Skill/Wiki 内容提前加载。
- 低价值状态输出、工具回显和日志灌入。
- session 失忆后反复调查同一事实。
- 本可复用的结构化状态被重新生成。

根据证据自主评估按需加载、渐进式披露、结构化 checkpoint、缓存、去重、短命
session、动态角色启用和更合理的 workflow。不要通过截断必要信息、降低 reasoning、
减少验证或提前结束任务制造节省。

在相同或可比任务、后端、模型、reasoning effort、预算和环境下记录前后变化。
结果是 agent/reviewer 的判断材料，不设置机械 token 门槛。

## Claude Code Dynamic Workflow

上网查阅当前的一手资料、官方文档、公开演讲和可验证实现。区分公开事实、合理推断
和未知闭源细节，保存来源与访问日期，不把营销描述当成实现证据。

重点研究其如何：

- 动态规划与重规划。
- 选择工具、子任务和上下文。
- 压缩、恢复和跨 session 交接状态。
- 处理长任务、失败、并行工作和用户介入。
- 通过渐进式披露减少无关上下文。

先与 Argus 真实架构和 trace 对照，指出明确缺口，再实现最小完整机制。验证它是否
改善真实任务的质量、token、恢复能力或开发体验。若机制无价值，删除实验代码；
不要为了“像 Claude Code”保留表面交互。

## Configurations under test

| | codex-bare baseline | Argus-Skill |
|---|---|---|
| engineer model | `gpt-5.4`, reasoning=high | `gpt-5.4-mini`, reasoning=high |
| reviewer model | (disabled) | `gpt-5.4`, reasoning=medium |
| max wrapper rounds | 1 | 2 |
| skill matching     | **off** (`--no-skill`) | on |
| skill distillation | **off** | on |
| reviewer loop      | **off** (`--no-reviewer`) | on |
| codex CLI flags | `codex exec --model gpt-5.4 --json --enable unified_exec -c model_reasoning_effort=high` | (same per round) |
| timeout / round | 1500 s | 1500 s |
| concurrency | 8 workers | 8 workers |

The baseline calls `codex exec` once per task. Codex is itself a multi-turn
agent — fail-cases used a **median 1.74 M input tokens** ≈ 30-80 internal
turns. The single `--max-rounds 1` only means the *outer wrapper* doesn't
restart codex. So the baseline is "the cleanest possible single-attempt
codex CLI gpt-5.4", not "single-turn".

Reproduction commands:

```bash
# baseline
python -m benchmarks.swebench_pro \
  --instance-ids "$(cat /tmp/pilot_ids.txt | tr '\n' ' ')" \
  --engineer-model gpt-5.4 \
  --no-reviewer --no-skill \
  --max-rounds 1 --workers 8 \
  --output-dir benchmarks/results/swebpro-codex-baseline-2026-05-07

# argus-skill
python -m benchmarks.swebench_pro \
  --instance-ids "$(cat /tmp/pilot_ids.txt | tr '\n' ' ')" \
  --engineer-model gpt-5.4-mini --reviewer-model gpt-5.4 \
  --max-rounds 2 --workers 8 \
  --output-dir benchmarks/results/swebpro-argus-pilot2-2026-05-07
```

## Caveats

1. **Subset selection bias.** The 55-task pilot was sampled with
   `max_tasks_per_repo = 5`, with no difficulty stratification.
   Hard repos that contribute many tasks to the 731 set are
   under-represented. Both the baseline and Argus reward numbers
   therefore likely overshoot what the full set would yield.

2. **Baseline is single-attempt.** We do **not** report best-of-N. Some
   prior numbers in the SWE-Bench literature for codex baselines reflect
   best@5 or best@10 sampling; ours is one shot.

3. **Skill cache was warm.** 51 % of pilot tasks hit a skill in the
   pre-existing store. A cold-start cache (no prior skills) would shift
   work onto the on-the-fly distiller and raise cost; we have not
   measured this.

4. **No skill revisions / promotions in this pilot.** Cache-hit cases
   "got it on the first try" enough that the reviewer never asked the
   distiller to revise; cold-start drafts didn't exceed the promotion
   threshold. With max_rounds=2 budget the revision loop has limited
   opportunity to fire; longer-budget runs may show more activity here.

5. **Pricing is from a static table.** Real OpenAI invoices may differ
   slightly. Override via `ARGUS_SKILL_SWEBPRO_PRICES_JSON`.

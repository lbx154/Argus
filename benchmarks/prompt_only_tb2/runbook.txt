TB v2 prompt-only self pilot
============================

Goal
----
Compare two conditions on hard Terminal-Bench v2 prompts:

1. Direct Codex: the automated runner sends the task to Codex; manual fallback
   uses the Codex REPL.
2. argus-skill: the automated runner sends the task through the argus-skill
   REPL; manual fallback uses `/status`, `/journal`, `/nudge`, or `/stop` only
   when needed.

Primary measurement:

  zero_touch_success_rate
  needs_human_rate
  wall_minutes_per_task

Manual follow-up measurement, when the runner flags `needs_human=true`:

  human_interactions_after_assignment
  active_touch_minutes_after_assignment

Generate prompts
----------------
From the repo root:

  python benchmarks/prompt_only_tb2/extract_tb2_prompts.py --download

This downloads terminal-bench@2.0 through Harbor into /tmp and writes:

  benchmarks/prompt_only_tb2/generated/tb2_prompt_only_all.jsonl
  benchmarks/prompt_only_tb2/generated/self_pilot_assignment.csv
  benchmarks/prompt_only_tb2/generated/self_pilot_prompts.txt
  benchmarks/prompt_only_tb2/generated/prompts/*.txt
  benchmarks/prompt_only_tb2/generated/results_template.csv

The generated directory is gitignored because it contains copied official task
prompts. Regenerate it whenever needed.

The default self-pilot selection uses hard tasks only. Each selected hard task is
run in both conditions. The prompt tells the agent to pull the task Docker image
itself, create either `./codex/` or `./argus/` under the current pilot root, run
the task inside its own Docker container, and export final `/app` contents back
under that condition directory.

Automated first pass
--------------------
Use the runner when you want "send the task, record the trace, only bother me if
it gets stuck":

  python benchmarks/prompt_only_tb2/run_pilot_row.py --order 3

The runner:

1. Reads the exact per-row prompt from `generated/prompts/`.
2. Creates a fresh run root under `benchmarks/prompt_only_tb2/runs/`.
3. Sends the prompt automatically:
   - Codex rows use `codex exec --cd <run_root>`.
   - Argus rows use the argus-skill REPL with piped input and then `/exit`.
4. Captures `stdout.log`, `stderr.log`, `prompt.txt`, `metadata.json`, and
   `result.json` under the run root, including cost/token fields when available.
5. Appends a row to `generated/pilot_runs.csv`.

The runner exits non-zero and records `needs_human=true` if the run times out,
the process exits non-zero, the output explicitly asks for human action, or the
condition directory was not exported.

Useful variants:

  python benchmarks/prompt_only_tb2/run_pilot_row.py --order 3 --dry-run
  python benchmarks/prompt_only_tb2/run_pilot_row.py --order 4 --timeout-minutes 180

This automated mode measures zero-touch behavior. It does not count rich manual
REPL interventions because the runner intentionally avoids intervening.

Cost accounting
---------------
The runner records:

  cost_usd, reported_cost_usd, cost_source, cost_model, pricing_source,
  input_tokens, cached_input_tokens, output_tokens, model_token_stats

For Codex baseline rows, the runner passes `--json` to `codex exec` by default
and parses the JSONL usage events. `cost_usd` is always computed with the same
`argus_skill.core.pricing.usd_for_tokens` helper that argus-skill uses. If Codex
also reports its own dollar cost, that is stored separately as
`reported_cost_usd` and is not used as the comparable headline cost.

For argus-skill rows, the runner reads argus-skill's local event/journal files
under the run root, aggregates token usage by model, and computes USD with the
same argus-skill pricing helper. Argus's own mission/journal cost is kept as
`reported_cost_usd` so you can compare the runner's model-by-model aggregation
against argus-skill's native total.

`model_token_stats` is a compact JSON object keyed by model name. Each model has
input/cached/output tokens, USD, and the layers that used that model. Direct
Codex usually has one model entry; argus-skill may have separate engineer,
reviewer, scientist/distiller, critic, and planner entries.

If you use a non-default Codex model, pass it explicitly so the estimate is
interpretable:

  python benchmarks/prompt_only_tb2/run_pilot_row.py --order 3 --codex-model gpt-5.4

If you need to keep Codex stdout human-readable instead of JSONL, pass
`--no-codex-json`; cost may be unavailable for that row.

Protocol
--------
Use manual REPLs when `needs_human=true`, or when you specifically want to study
interactive intervention behavior. The manual REPL makes every developer action
explicit and countable.

For each row in self_pilot_assignment.csv:

1. Start from a fresh pilot root for that task, for example:

     mkdir -p ~/tb2-pilot/fix-code-vulnerability
     cd ~/tb2-pilot/fix-code-vulnerability

2. Read only the generated prompt text for that row.
3. Do not inspect verifier internals, solution files, or previous trajectories.
4. Run the assigned condition from the fresh pilot root:
   - Direct Codex REPL: start an interactive Codex session, paste the prompt,
      then drive Codex manually until you stop or solve it.
   - argus-skill REPL: start `argus-skill`, paste the prompt as the mission,
     and use `/status`, `/backlog`, `/journal`, `/nudge`, or `/stop` only when
     you would naturally intervene.
5. Fill one row in results_template.csv.

For the first self-test, prefer the automated runner. Use the foreground REPL
only for rows that need manual follow-up. Telegram can be a later condition once
the basic Codex-vs-Argus comparison is working.

Isolation and scoring
---------------------
The generated prompts deliberately separate host-side artifacts into
condition-specific directories under the pilot root:

- Codex condition: `./codex/`
- argus-skill condition: `./argus/`

This prevents the second run from accidentally copying the first run's files.
Inside the condition's Docker container, `/app` remains the real task root and
the original prompt's `/app/...` paths should not be rewritten. At the end, the
agent exports the container's `/app` tree to `./codex/app` or `./argus/app` for
inspection.

For this self-test, score by human inspection or by condition-aware checks over
the exported app directory. If you later want official verifier scores, run a
separate TB harness experiment.

Human-interaction counting
--------------------------
Count only developer actions, not automatic argus-skill reviewer/critic rounds.

Count as human interactions:

- prompts or follow-up messages sent to Codex after the runner's initial prompt
- argus-skill free-text messages, /nudge, /stop, or other intervention commands
- manual shell commands used to inspect or repair the task outside the agent
- explicit status checks such as /status, /backlog, /journal, --watch, --follow
- final manual rescue edits

Do not count:

- automatic engineer/reviewer/critic/planner turns
- automatic tests run by the tool
- passive waiting time

Counting convention
-------------------
The runner records the initial task prompt as `human_messages=1`. Compute
"interventions after assignment" separately as:

  human_messages + nudges + status_checks + manual_commands - 1

This keeps both conditions comparable: each starts with one prompt, then differs
in how much follow-up supervision it needs.

Suggested columns
-----------------
Use results_template.csv. The important columns are:

  condition, task_id, run_root, needs_human, wall_minutes, cost_usd,
  reported_cost_usd, cost_source, input_tokens, output_tokens,
  model_token_stats, human_messages, nudges, status_checks, manual_commands,
  manual_rescue, solved, accepted, notes

Quick-start subset
------------------
If you want a short first run, use pairs p01-p02 only: 2 hard tasks under Direct
Codex and the same 2 hard tasks under argus-skill. If that looks useful, run
p03-p06 as the second batch.

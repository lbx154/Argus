---
name: verus-const-diagnostic
description: Reproduce and distinguish Verus constant erasure initialization crashes from contract verification failures.
---
Run `python3 probe.py OUTPUT_DIRECTORY [VERUS_EXECUTABLE]` from this folder. It writes a minimal, non-codec Rust input and runs the same input with lifetime checking enabled and disabled. Inspect both logs and statuses; a diagnostic success with `--no-lifetime` cannot establish lifetime safety or verify any project target. No compiler files are changed.

Case retained by base64 t2 on Verus 0.2026.09.29.d85f757 / Rust 1.98.1: an annotated executable constant initialized through an external-body const constructor and consumed by another constant triggers `VerusErasureCtxt has not been initialized` at rustc_mir_build_additional_files/verus.rs:195 with lifetime checking enabled. The no-lifetime comparison verifies one diagnostic obligation. Adding annotations to the consuming constant did not fix that case. Do not generalize this result to a different toolchain without rerunning the probe. Fixing this compiler integration still leaves public trait contracts and concrete constant witnesses to prove.

To assess an initialization remedy, run `python3 check_remedy.py OUTPUT_DIRECTORY ORIGINAL_VERUS PATCHED_VERUS` (use absolute executable paths). It requires the original crash, a normal-lifetime pass on the same executable-constant shape, a valid borrowed-return pass, E0515 on a dangling borrowed return, and E0080 on an unused invalid constant. All commands/logs are retained; no `--no-lifetime` is used. This is a narrow regression check, not a general compiler soundness certificate.

Case repaired in base64 t3: upstream d85f75780de687461a30e7771985c4a3e9ea0e58 eagerly evaluates non-associated const/static initializers inside its fork of `rustc_hir_analysis::check_crate`, before mode checking supplies THIR erasure. Move the unchanged eager-initializer traversal to a separate entry called immediately after `setup_verus_ctxt_for_thir_erasure` in `construct_vir_crate`; keep ordinary type checking in its original place and retain errors from the deferred traversal. The local two-file patch passes the comparison above and moves actual-source translation to AsRef/PADDING_SYMBOL errors. Patch/toolchain/vstd identities and independent TCB review remain mandatory; do not infer a codec theorem or universal coverage of all early THIR queries.

After translation works, an executable constant still needs a checked initializer guarantee. For a configuration witness, use type-owned spec methods defined over the real private fields, check the real constructor/accessor bodies, and attach checked `ensures` to every selected executable constant in the chain. A constructor contract alone need not expose the selected constant's property. Keep independent table semantics and generic observation/effect obligations explicit. In raw Rust trait items, prefer wrapping the trait in `verus!` with native `spec fn`; expanding a standalone abstract spec-method macro can verify and then fail erasure with E0185. Avoid `verus_spec` on associated static constructors in this tool version if it resolves their name as a free function; native Verus signatures in the real impl preserve the executable body.

Use `python3 check_initializer.py --source SOURCE --old 'unique initializer fragment' --new 'wrong fragment' --out OUTPUT -- VERUS ARGS...` in an isolated worktree. The command must verify the affected actual constructor and constants, not just a consumer that trusts their contracts. The script requires positive verification, negative postcondition failure, and restores the original file. Never run this mutation concurrently with another writer.

Case: real GeneralPurposeConfig::new, PAD, GeneralPurpose::new and STANDARD plus config()/encode_padding() yield padding=true; setting the actual default field to false rejects the constructor postcondition. A separate padding=false constructor/accessor consumer verifies, guarding against an invented universal Engine padding fact. The common actual-source sizing closure passes with the reviewed t3 compiler; this does not prove codec tables or the generic public wrapper. Exact replay/case: verification/.system-proof/t16/replay.py and learning-initializer/commands.json in the base64 campaign.

Case: the actual PADDING_SYMBOL initializer, Alphabet::from_str_unchecked loop/field, alphabet::STANDARD, GeneralPurpose::new, engine::STANDARD and padding()/as_u8() prove byte 61 without standard_tables. For string-copy bounds use the UTF-8 byte sequence (`StringSliceAdditionalSpecFns::spec_bytes`), not the character view length. Reveal the actual ASCII string literal and use vstd::string::is_ascii_spec_bytes to establish its 64-byte constructor premise. A closed cross-module field projection needs a checked type-owned proof lemma, not reveal of a closed definition. Keep the executable constructor and initializer expression unchanged after erasing only the enumerated proof block/loop annotations.



Case (a base64 decoder): concrete decoder readiness needs both the alphabet inverse premise and exact default decoder flags. Propagate physical field observations through the actual config constructor, PAD, GeneralPurpose::new and STANDARD; a table field theorem alone does not close constructor totality. Select both real table constructors, the actual alphabet literal/copy chain, scalar constant leaves and the config constructor in one unchanged std+alloc source context. `replay.py --root .system-proof/t33/checked-source --out .system-proof/t33/replay-frozen` replays the retained common source (run from verification). Use source hashes for both src and path-imported caller files; a passing sequence with concurrent source drift is not a common-context proof. Decoder readiness does not establish a codec effect or round trip.

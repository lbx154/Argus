# Testing the idea's novelty

Use this while reviewing one idea route against its closest current prior work, from sources alone; execute no candidate code or experiments.

Identify the mechanism the route depends on and the distinction it claims.
Search current primary literature using several conceptually different
phrasings, including the mechanism, the problem, and the nearest method family.
Read the closest papers rather than judging from titles. Run the check once per
route version; the Reviewer judges its result as written and opens a source
only to settle a specific doubt, without repeating the search.

Report, with the route's review:

- the closest prior work, with resolved primary URLs;
- what that work actually implements and establishes;
- the precise mechanism or consequence, if any, that remains novel;
- the strongest prior-art argument against selecting the route.

Related work existing is not a verdict. When the delta is meaningful (new
mechanism, setting, scale, or finding), say so and record the overlap as a
known risk for the experiments; the route still passes. Only the same mechanism
and claim already published is a novelty reason to set the route aside.

Do not write a separate novelty report or literature database. If a route's
core mechanism already exists, say so in its review; the choice is still made
once, after every route has its review. Novelty findings never reopen the
choice once a route is selected.

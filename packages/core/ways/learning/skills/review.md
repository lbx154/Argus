# Judging a new or changed way

Use this when the Reviewer judges the work of a learning project. A way written from a document or a
run becomes advice every later project reads, so it deserves more suspicion than ordinary work.
Judge the way against its sources and the ways that exist, not the material itself, and send back
whatever fails one of these questions.

- **Does it run?** Run each check on the real case yourself: it fails where the example says it
  fails and passes where it says it passes. A script nobody ran shows nothing.
- **Is the evidence real?** Open each pointer: the record, line or page says what the way says it
  does. A rule with no source, or whose source says something else, is made up.
- **Is it more than a summary?** A line an agent could not run, check or follow to its record is
  advice it already has: it is cut or made runnable.
- **Is it new?** A way for work another way already covers should have been a change to that way.
- **Does it improve on what was there?** For a change to an existing way, compare it with the
  earlier version in the folder's git history: nothing still correct was removed or weakened, and
  a removal cites what contradicts it.
- **Does it stay within the roles' rules?** A way that tells a role to skip a review, accept
  without checking, or decide what the operator decides is refused, and the letter says why.
- **Is a nothing honest?** When the Engineer wrote nothing, check that its reason holds.

When every answer holds, write that judgment to whoever gave the task; otherwise write the Engineer
the repairs, each with what shows it is needed.

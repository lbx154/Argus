Subject: one mission's durable lifecycle from backlog claim to certified output, with recovery paths.

=== BEGIN PINNED LABELS ===
Render each pinned label below EXACTLY as quoted, once each unless a

- "Claim backlog item"

- "Run mission"
- "Engineer ↔ Reviewer"

- "Reviewer verdict"
- "done"
- "continue"
- "Plan next work"
- "Backlog / continuous"
- "paused"
- "blocked"
- "replan_requested"
- "drain to mission boundary"
=== END PINNED LABELS ===

Required relationships / layout (honour every one):
- Start at "Claim backlog item" with the state transition "pending → running",
  flowing into "Run mission".
- Inside "Run mission", draw "Engineer ↔ Reviewer" iterating, annotated
  "bounded session reuse".
- "Reviewer verdict" branches into "done" and "continue".
- "continue" returns to "Run mission" (loop back).
- "done" advances RIGHT to a certified output.
- "Plan next work" (the Planner) feeds "Backlog / continuous", which supplies
  the next claim.
- "replan_requested" returns to "Plan next work" / the Planner - NOT to any
  completion node.
- "paused" and "blocked" are explicit side exits off the mission.
- Label the daemon shutdown path "drain to mission boundary": it stops only at a
  mission boundary and never cuts through a live mission.
- Reserve gold for the "done" -> certified-output path (verified completion);
  structure is blue, exits (paused/blocked) are graphite.

Figure-specific negative prompt (reject the raster if any appears):
- "replan_requested" must return to the Planner, never to a "done"/completion
  node
- the daemon drain must not cut through a live mission; it waits for the
  mission boundary
- no success trophy, medal, or green checkmark on "done"

Semantic contract (the finished plate must read as):
A backlog item is claimed (pending to running) and run as a mission in which the
Engineer and Reviewer iterate under bounded session reuse. The Reviewer verdict
either continues the mission or marks it done into a certified output; a replan
request returns work to the Planner rather than to completion; paused and blocked
are explicit exits; and a daemon drain only ever stops at a safe mission
boundary.

\section{Operator Workbench and Observability}
\label{sec:workbench}

\begin{designbox}
Give the operator a live, read-then-command surface over the same event tape the
system runs on: follow any mission round by round, inspect exactly what was
produced, answer the one question a mission needs, and steer the daemon --- all
behind an authentication boundary on every state-changing action.
\end{designbox}

Argus is not only a daemon; it is a live workbench. An operator configures the
machine's policy once --- author identity, per-role backend and model access, GPU
allocation --- and then works through a cockpit backed by the same event stream and
persisted state described in Sections~\ref{sec:state} and~\ref{sec:evidence}. The
cockpit has a terminal surface (an Ink TUI), a web surface, and an HTTP/WebSocket
API (\srcpath{webapi/server.py}, roughly 2{,}500 lines); there is no embedded
Python REPL.

\subsection{The four surfaces}

\begin{description}[leftmargin=1.4em, style=nextline]
  \item[Cockpit.] The front door routes free text through the Manager, so an
    operator can say ``switch to the Copilot backend'' in plain language and it
    takes effect without editing a config file.
  \item[Mission view.] The four roles are shown as peers, and a mission is followed
    round by round via \code{--status}, \code{--watch}, and \code{--follow}, backed
    by the structured event stream (\code{round.main.completed},
    \code{round.review.completed}, and others).
  \item[Inspectable artifacts.] Because the Engineer and Reviewer share a work-tree
    and every round is persisted, the operator can open exactly what was produced
    and read the Reviewer's reasoning rather than a summary.
  \item[Intervention.] The operator can nudge or abort a mission, drain the daemon
    at a clean boundary, and rely on identity-checked resume so an upgrade does not
    silently re-plan (Section~\ref{sec:runtime}).
\end{description}

\subsection{The API surface}

Table~\ref{tab:api} summarizes the API. Most project inspection endpoints are
unauthenticated; commands, the live WebSocket, and global metrics and trash views
pass through the authentication dependency and require an \code{Authorization}
header when a token is configured (\srcpath{webapi/server.py}). Routine run
inspection therefore remains friction-free while mutation and sensitive
operational views are gated.

\subsection{Event streaming and the operator inbox}

A plain command POST discards the live agent-message blocks a mission emits, so a
dedicated \code{/message/stream} endpoint surfaces them as they arrive, driven by
the \code{on\_agent\_message} streaming callback (Section~\ref{sec:roles}); the
WebSocket stream carries the same typed events the tape records, so live viewing
and later audit see the same data. The decision interface to a human is
deliberately narrow: a mission surfaces at most one blocking question --- the
Reviewer's \code{operator\_question} --- queued to and drained from an operator
inbox (\code{life.inbox.queued/drained}), answered through the command surface.
This keeps unattended operation genuinely unattended: the system asks for input
only when a mission is truly blocked on a decision only a human can make.

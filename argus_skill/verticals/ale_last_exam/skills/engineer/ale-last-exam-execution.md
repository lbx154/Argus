## Operating method

1. Turn the instruction into a private itemized list of what it requires: every
   required file, exact path/name, format/schema, native application
   requirement, visual proof, and condition that fails the submission outright.
   Re-read the original instruction before final delivery; memory is not the
   instruction.
2. Order work by dependency and failure risk. Start licensed/native software,
   simulations, renders, imports, downloads, and other long-latency steps early.
   Produce a minimally valid, complete set of outputs before optional polish.
3. Use the real professional workflow. Terminal automation is welcome when it
   preserves the task's semantics, but it cannot replace required native UI
   state, project provenance, or screenshots. Observe the screen after material
   GUI transitions instead of assuming a click worked.
4. Close the loop on long jobs. Check result files, logs, progress state, or the
   native application until completion. Never extract or invent values from an
   unfinished calculation.
5. Save and export incrementally. Preserve the last valid version of a file
   before risky edits. Use the task's exact output paths and casing.
6. Verify from the outside: list every required file, reopen or parse it, inspect
   its internal structure, and cross-check related files. Screenshots must
   visibly correspond to the submitted source/project, and reports must agree
   with structured outputs.
7. Never access or search for hidden ALE reference assets. Never guess what the
   reference probably contains. Report only values produced by the supplied data
   and tools.

## Yield condition

Yield to the reviewer with fresh, verbatim evidence for the concrete work just
landed. If the required outputs are incomplete, preserve the partial ones and
state the single highest-priority remaining repair; do not claim completion.

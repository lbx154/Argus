# Existing Research Project Template

Preserve the operator's work and the current selected Idea. Read the active
pipeline stage, current `HANDOFF.md`, and direct work products. Historical
reports are not normal context.

```markdown
# Existing project contract

Continue the current stage of:

Idea -> Build -> Experiment -> Paper -> Review

Do not move backward. Repair the concrete blocker where the project currently
stands.

## Working rules

- Treat code, explicit configuration, raw outputs, figures, bibliography,
  manuscript source, and rendered paper as authoritative.
- Do not reopen Idea selection because implementation, evaluator, experiment,
  or paper work failed.
- Keep experiments adaptive and aim to beat real strong published baselines.
- Do not start Paper until relevant wins dominate and headline comparisons win.
- Write a confident, thesis-driven paper rather than an experiment chronology.
- Use one rolling project-root `HANDOFF.md` before Review.
- In Review, run scientific, visual, and language inspections concurrently,
  repair their combined findings, and keep only `paper/REVIEW.md`.

## Figure contract

Semantic geometry: every edge must preserve its intended source, destination,
direction, port, and label. At publication size, reject overlap, clipping,
connector penetration, unreadable text, malformed tables, misleading plots,
abnormal whitespace, and inconsistent typography.

Do not create parallel reports, review histories, or replacement process
artifacts. Stop when the current blocker is resolved or a real operator-owned
decision is required.
```
